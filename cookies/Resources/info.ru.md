# Подмена значения в cookie

В DevTools открываем cookies и видим пару `key=value`:

```bash
I_am_admin 68934a3e9455fa72420237eb05902327
```

Пробуем разобрать захэшированное значение: отправляем его в сервис md5 decrypt (например, [https://md5decrypt.net/](https://md5decrypt.net/)) и получаем строку `"false"`. Аналогично хэшируем строку `"true"`, подставляем полученный хэш в cookie и успешно получаем флаг.

## Разъяснения

### Хэширование

Хэширование — это превращение данных в шестнадцатеричную строку фиксированной длины с помощью хэш‑функции определённого алгоритма.  
Хэш нужен для:
- сравнения данных по этой строке (быстрая проверка «одинаково или нет»);
- хранения данных в закрытом виде (например, пароли в базе — в виде хэшей);
- проверки целостности данных (файл не менялся по пути).

При необходимости можно попробовать определить, какой алгоритм хэширования использовался, с помощью онлайн‑инструмента, например:  
[https://toolk.io/ru/tools/hash-identifier](https://toolk.io/ru/tools/hash-identifier).

### Cookies

Cookies — это текстовые данные, которые сайт сохраняет в браузере, чтобы хранить информацию о сессии пользователя: язык, настройки (тема), рекламные метки, корзина, различные настройки, идентификатор сессии и т.п. Пока cookie хранятся в браузере, сайт может использовать эти данные.

Cookies могут стать источником уязвимостей, если не использовать флаги безопасности: `HttpOnly`, `Secure`, `SameSite`.

- **HttpOnly** — защита от доступа к cookie через JavaScript (нельзя прочитать через `document.cookie`).
- **Secure** — разрешает передавать cookie только по HTTPS (данные отправляются не в открытом виде, а по зашифрованному каналу).
- **SameSite** — управляет межсайтовой передачей cookie (помогает защищаться от CSRF).

## Почему мы нашли флаг

1. Сайт доверяет cookies. На сервере нет надёжного серверного хранения и проверки признака `is_admin` (роль фактически определяется значением на стороне клиента).
2. Хэш для проверки роли admin предсказуем: это просто `md5("false")` / `md5("true")`, без секрета на стороне сервера.

Это похоже на уязвимость **Web Parameter Tampering** (манипуляция параметрами / cookies):  
[https://owasp.org/www-community/attacks/Web_Parameter_Tampering](https://owasp.org/www-community/attacks/Web_Parameter_Tampering).

## Какой вред можно нанести этой манипуляцией? 
Если брать в приме наш случай, когда пользователь получает права админа, то последствия очень серьезные, фактически взломщик получает полную власть над сайтом, и имеет доступ к персональным данным пользователей, внутренним отчетам, статистике, платежным данным + может править контент, менять настройки приложения
